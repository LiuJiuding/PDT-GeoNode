# `spec/` —— L0 最小规范（**用户手写，agent 只读**）

这个目录是这个仓库的**决定层**：一个主题一页，只写"要什么、不允许什么、怎么算通过"。
它比 `../docs/manual/`（细则 + 可执行例子）短得多，是给架构师看和改的那一份。

三层的分工与流程见 `../docs/10-文档分层与协作规范.md`；这里只规定**格式**与**所有权**。

## 所有权（机械可查，不靠自觉）

* 每个 L0 文件的前三行必须有 `<!-- owner: user; agent: read-only -->`。
* **agent 不修改本目录下除 `README.md`、`coverage.md` 之外的任何文件**（那两份是 agent 维护的）。
* agent 发现 L0 缺失、含糊或自相矛盾时：**不改**，只在回复里提"建议 L0 增补/澄清 N 条 + 推荐措辞"。

## 篇幅与内容预算

* 一个主题一页。
* **只允许这五段**：`目标` / `契约` / `不变量` / `验收` / `明确不做`。
  （2026-09-14：原先单列的 `不可协商的边界` 已取消，那类内容统一并入 `明确不做`；
  旧的 `## 边界` 写法也一并改名。解析器不校验标题，但**新条目一律用这五个**。）
* **禁止写入**：实现机制、代码路径、实测数字、坑与历史、算法细节——那些属于 L1/L2。
  判断标准：你改这一行，会不会需要我跟着改实现？会 → 它本来就该待在 L0；
  不会、只是"怎么做到的" → 它属于 L1/L2。

## 条目格式（`pdt_spec.py` 按这个解析）

不变量一行一条，**编号**放在行首的粗体里，**slug**放在行尾的隐藏注释里：

```markdown
## 不变量
- **MMB-1** 只读：不改场景与选择；临时求值产物结束即回收。 <!-- wr:id=read-only -->
- **MMB-2** 命中判据与 Blender 自身一致：……（含 UI 缩放不是 100% 时）。 <!-- wr:id=hit-test -->
```

* **编号是给人看的标签**：形如 `<主题前缀>-<序号>`（`MMB-1`、`PICK-3`…），前缀通常取主题缩写。
  编号**可重排、可增删、可复用**，只保证在同一份 L0 里当时唯一——它**不承诺稳定**，重排不必通知谁。
* **slug 是给机器读的身份**：每条不变量行尾带一个渲染后看不见的注释 `<!-- wr:id=<slug> -->`，
  slug 用小写 ASCII 与连字符（`point-read-domain`），**只增不改**：
  拆分时新条目取新 slug；合并 / 删除时把被并入方或已删方的 slug 记进 `coverage.md` 的编号快照
  （写"已并入 `<slug>`" / "退役"）。没带 slug 的条目按编号兜底、`pdt_spec.py` 照旧工作，
  但**一重编号就会失联**（`slugs` 会把它列出来），所以落新条目时顺手带上。
  改标题不影响身份——只有 slug 决定"还是不是同一条"。
* **下游只引用 slug 或概念**：L1 的章节锚点、测试注释、代码注释都不引用编号；`coverage.md` 是
  **唯一的映射表**（slug ↔ L1 章节 ↔ 测试 ↔ 状态），**当前编号由工具现算、不落盘**，
  所以重编号不需要改任何下游文件。
* **历史保留当时的编号**：`docs/14-…` 一类历史文本不追改；`coverage.md` 末尾的「编号快照」把每个历史
  编号对到 slug 与现状，读历史时照那张表查（每次重编号追加一段，新的在后）。
* 一行可以很长，但**只表达一个可判定的性质**；一条不变量如果没法用一个测试或一次现场测量
  确认，就说明它还没写成"不变量"。

## 覆盖表与自检

`coverage.md`（agent 维护）把每个 L0 条目对到 L1 章节与测试，并记录核对时 L0 文件的内容哈希。
**表的键是 slug，不是编号**，所以重编号之后这张表一个字都不用改：

```powershell
python tools\pdt\pdt_spec.py list     # 列出条目（编号 + slug）与它落在哪
python tools\pdt\pdt_spec.py slugs    # 只列身份：编号 -> slug，缺 slug 的用 --patch 给出要贴的行号
python tools\pdt\pdt_spec.py check    # 报告：条目没被覆盖 / 覆盖表指向不存在的条目 / 路径失效 / L0 已改
python tools\pdt\pdt_spec.py sync     # 核对完 L1 与测试之后，刷新记录下来的 L0 哈希
```

`slugs --patch` 的输出形如 `line 47: append <!-- wr:id=point-read-domain -->`，照着贴即可。
`check` 是**建议性**的（默认退出码 0，不挡任何事），由 `run_tests.ps1` 末尾打印；
需要让它挡 CI 时用 `--strict`。

## 写作参考与模板（新主题从这里起步）

* `../templates/L0-参考.md` —— **写作参考**：`pdt_spec.py` 真正校验的机械规则、可复制骨架、
  五段各自回答什么、现有四份 L0（`node_info` / `viewer_overlay` / `pdt_selection` / `selection_pick`）的写法拆解、
  好例子 vs 坏例子、覆盖表契约、改完 L0 之后 agent 会做什么、常见坑。
* `../templates/_L0_TEMPLATE.md` —— **空白骨架**，复制到 `spec/<主题>.md` 再填。
* 注意：`spec/` 目录下**只能放 L0 与这两份簿记文件**（`README.md`、`coverage.md`）——
  放参考、草稿或旧版备份会被当成 L0 解析并报"no `**ID**` items found"。
