# 选择字符串语法（规范）

> **本文档是规范性的。** 节点求值、Python 解析器、面板摘要、UI 提示文字与测试期望值
> 都以这里为准。改语义必须先改本文档。

选择字符串（selection string）是一行文本，描述"哪些元素被选中"。它借用了 Houdini 的
group syntax：`0-10 rim ^5` 表示"0 到 10、加上 `rim` 组、再去掉 5"。

求值结果是**一个布尔集合**：对 `Domain` 选定的元素域，每个元素要么选中要么不选中。
节点把这个集合作为 `Boolean` 字段输出。

> 全文里的"元素"指的都是 `Domain` 选定的**那一种元素**（网格顶点 / 边 / 面、曲线控制点 /
> 样条、点云的点、顶层实例之一，见[节点页](../nodes/pdt_selection.md#domain元素种类)）：
> 一个几何集合里同时有多种组件时，只有 `Domain` 对应的那个组件参与求值，其余恒为假。

---

## 1. 求值模型：一个累加器，从左到右

理解全部语法的关键只有一句话：

> **从左到右一个累加器。每个记号要么往里面加东西、要么从里面减东西、要么和它求交。**

```
初始集合  ──▶ 记号1 ──▶ 记号2 ──▶ 记号3 ──▶ 最终选择
```

没有优先级、没有括号嵌套的结合律、没有"先算交集再看并集"。
`A &B 0` 是 `((A ∩ B) ∪ {0})`，**不是** `A ∩ (B ∪ {0})` —— 这是本语法的核心，
也是它和"集合表达式"最不一样的地方。

### 1.1 初始集合（规范）

**初始集合是空集**，除非整个表达式里**一个"加"记号都没有**——也就是每个顶层记号都以
`^` 或 `&` 开头——此时初始集合是**全集**。

| 表达式 | 有"加"记号？ | 初始集合 | 结果 |
| --- | --- | --- | --- |
| `A` | 有 | 空 | `A` |
| `^A` | 没有 | **全集** | 全集 − `A` = "除了 A 以外的全部" |
| `&A` | 没有 | **全集** | 全集 ∩ `A` = `A` |
| `^A ^B` | 没有 | **全集** | 全集 − `A` − `B` |
| `!A` | **有**（`!` 是"加补集"） | 空 | ¬`A` = "除了 A 以外的全部" |

**注意 `^A` 和 `!A` 结果一样、走的路径不同**：前者从全集里减，后者从空集里加补集。
混合时差别就出来了（见 §3.4）。

### 1.2 四个运算（规范）

记 `P` 为某个记号"匹配到的元素集合"，`acc` 为当前累加器：

| 记号 | 名称 | 语义 | 等价写法 |
| --- | --- | --- | --- |
| `P` | 加 | `acc ← acc ∪ P` | — |
| `^P` | 减 | `acc ← acc \ P` | `acc ∩ ¬P` |
| `&P` | 交 | `acc ← acc ∩ P` | — |
| `!P` | **加补集** | `acc ← acc ∪ ¬P` | — |

> **`!` 不是"取反"，也不"切换"任何状态。** 它把 `P` 的**补集并进**累加器。
> 这一点很重要，因为它让 `!` 和 `^` 在**单独出现时**结果相同、在**跟别的记号混合时**完全不同：
> `A !B` 是 `A ∪ ¬B`（几乎总是"全部，除了 B 里不属于 A 的那部分"），**不是** `A \ B`。
> 想要"从 A 里去掉 B"就写 `A ^B`。

### 1.3 子表达式 `{ ... }`（规范）

`{ ... }` 是**一个操作数**：它内部按同样的规则（包含 §1.1 的初始集合规则）**独立求值**出一个集合，
然后这一个集合作为整体，按外层的运算符合并进外层累加器。

```
{arm* ^arm2}          → 内部 = arm* \ arm2，整体作为一个"加"
0-10 &{arm* ^arm2}    → 把上面那个集合与 0-10 求交
!{arm*}               → 上面那个集合的补集，并入（空集起步）
```

内部**不会**看到外层的累加器，外层也**不会**把子表达式内部的记号单独算一遍。

### 1.4 组件与域的范围（规范）

一个几何集合里可以有**多个组件**（网格、曲线、点云…）。求值是**按组件分别进行**的：
同一个选择字符串会**独立地**作用到每一个组件上，序号在各组件自己的域里解释
（`4` 既选中网格的第 4 个点，也选中曲线的第 4 个控制点）。

节点的 `Component` 输入（`Any` / `Mesh` / `Curve` / `Point Cloud` / `Instances`）**限制作用范围**：
不在范围内的组件**全部为假**。`Any` 是默认值，等于"每个组件各自求值"。

`Domain` 说"索引指哪一种元素"，且**必须和 `Component` 搭配**，否则是**错误**：

| Component | 可用的 Domain |
| --- | --- |
| `Any` | 全部：`Point` / `Edge` / `Face` / `Spline` / `Instance` |
| `Mesh` | `Point` / `Edge` / `Face` |
| `Curve` | `Point`（控制点）/ `Spline`（样条，`AttrDomain::Curve`） |
| `Point Cloud` | `Point` |
| `Instances` | `Instance`（`AttrDomain::Instance`，一个**顶层实例**一个序号） |

* **曲线的 `Spline` 域**：一根样条一个序号（跨样条扁平，和 `Point` 域一样按存储顺序）。
* **实例的 `Instance` 域**：只覆盖**顶层**实例，嵌套实例不单独编号；`@position` 可用
  （实例位置由 `instance_transform` 派生），`@ptnum`/`@elemnum`、`group:<名字>`、
  `@属性` 与其它域一致。
* 网格没有 `Spline`/`Instance` 域、曲线与点云没有 `Edge`/`Face`/`Instance` 域、
  实例没有除 `Instance` 以外的任何域——这些搭配会被**拒绝**，而不是静默选空。
* 实例域与其它域之间**没有插值**（Blender 的实例域是孤立的），把实例域字段接到点域
  消费者上是"什么都没选中"，这也是 Blender 本身的语义。

## 2. 词法：什么算一个记号

记号之间用**空白**或**逗号**分隔（`0-1,4-5` 与 `0-1 4-5` 等价）。这与 Houdini 一致。

* `{` 和 `}` **总是**自成记号，即使紧贴着别的字符写。
* 双引号 `"` 内的内容属于**当前记号**，引号本身不进入值：`@id="0-4 78"` 是一个记号。
* 前导运算符（`^`、`&`、`!`）与它后面紧跟的东西属于**同一个记号**：
  `^0-3`、`^ A` 都可以，但 `^0-3` 才是常规写法。
* `{` 前面的 `^`/`&`/`!` 会和 `{` 合并：`^{arm*}` 是一个记号。
* 字符串两端空白会被裁掉。

> ⚠️ **多段值列表必须加引号。** `@id=0-4 78` 是**两个**记号（`@id=0-4` 与 `78`），
> 含义是"id 在 0..4 **或** 序号 78"，**不是**"id 在 {0..4, 78}"。
> 要写值列表就加引号：`@id="0-4 78"`。逗号同理。

## 3. 记号详解

### 3.1 序号与区间

| 写法 | 含义 |
| --- | --- |
| `5` | 第 5 个元素 |
| `0-3` | 0、1、2、3（**两端都含**） |
| `0-100:2` | 0、2、4、…、100（步长 2，步长 ≥ 1） |
| `2-2` | 就是 `2` |
| `99` | 合法。**超出范围的序号只是"匹配不到"**，不是错误 |

非法：`5-2`（倒序）、`1-`、`-`、`:2`、`0-3:0`（步长 0）——都是**语法错误**。

### 3.2 `*`

`*` 是全集。单独写 `*` 就是"全选"；`* ^5` 是"除了 5 以外的全部"。

### 3.3 组

**组就是布尔属性 `group:<名字>`**——也就是 `Store Named Attribute` 节点里存一个
`BOOLEAN`、名字为 `group:A` 的属性。参数里写 `A`，读的就是 `group:A`。

| 写法 | 含义 |
| --- | --- |
| `rim` | 布尔属性 `group:rim` 为真的元素 |
| `arm*` | 名字匹配 `arm*` 的**所有**组，取并集 |
| `?*` | 名字至少一个字符的所有组 |
| `arm[0-9]` | 字符类；类内可用 `-` 区间与 `^`/`!` 取反（`[^0-9]`） |

* **通配符**：`*`（任意长）、`?`（恰好一个字符）、`[...]`（字符类）。
* 组名字符集：字母、数字、`_`、以及通配符 `* ? [ ]`；`[ ]` 必须配对。
  类内额外允许 `- ^ !`。`-` 和 `:` 在**类外**非法，所以 `a-b` 是语法错误。
* 组名**只认** `group:<名字>` 这个命名空间，没有回退、没有前缀猜测。
* 属性类型必须是 `BOOLEAN`。同名但是 `INT`/`FLOAT` 的属性会被当成**非组**并给出警告。
* 组所在的域与 `Domain` 不一致时，交给 Blender 自己的字段系统做域转换
  （和 `Named Attribute` 节点的行为一致）。
* **匹配不到任何组的通配符只是一个警告**，不是错误（G2）。

### 3.4 `!` 与 `^` 的区别（最容易踩）

`A !B` 和 `A ^B` 在 A、B 都非空时结果几乎总是不同：

| 表达式 | 含义 | A={0,1,2}, B={1,2,3} 的结果 |
| --- | --- | --- |
| `A ^B` | 从 A 里去掉 B | `{0}` |
| `A !B` | A 并上 ¬B | `{0,1,2,4,5,…}` 即"全部，除了 B\A" |
| `!A` | ¬A（空集起步，加补集） | `{3,4,…}` |
| `^A` | 全集减 A（全集起步） | `{3,4,…}`（与上一条同结果、不同路径） |
| `!A &B` | ¬A ∩ B | `{3}` |
| `A !B ^2` | (A ∪ ¬B) \ {2} | 上一条再减掉 2 |

**记法建议**：想"去掉"就用 `^`；`!` 留给"除了……以外的全部"这种真的需要补集的场合。

### 3.5 属性模式 `@`

```
@名字[.分量 | [分量号]] 比较运算符 值
```

**属性名**：`@position`（内置的点位置）、`@ptnum` / `@elemnum`（元素序号，
同名真属性优先）、或任意数值属性的名字。

> **没有 `@P` / `@x` / `@y` / `@z` 简写。** 节点按字面查属性名，
> `@P` 就是去找名叫 `P` 的属性，找不到会给警告并且什么都不匹配。
> 要读点位置请写 **`@position.x`**。（Houdini 里 `@P` 能用，这里不能用——这是有意的。）

**分量**：`.x/.y/.z`、`.r/.g/.b`、`.u/.v/.w` 三组等价，也可以写 `[0]`/`[1]`/`[2]`。
**不写分量时取第一个分量**（与 Houdini 一致）。

**比较运算符**：

| 运算符 | 含义 |
| --- | --- |
| `=`、`==` | 等于（也可接**值列表**，见下） |
| `!=` | 不等于（也可接值列表） |
| `>`、`<`、`>=`、`<=` | 数值比较 |
| `&` | **整数按位与**，非零即匹配（`@position.x&3`） |

**值**：

* `>`、`<`、`>=`、`<=`、`&` 的右边**必须是一个数**。写成 `@position.y>abc` 是**语法错误**
  ——否则一个笔误就变成"静默什么都不选"。
* `=`、`!=` 的右边可以是**值列表**：多个整数或整数区间，用空白分隔，**必须加引号**
  （见 §2 的警告）。
  `@id="0-4 78"` 表示 id 在 0..4 或等于 78；只有一个区间时不用引号：`@id=0-4`。
* **字符串属性不支持**：一个带引号、又**不是**数值列表的值会被当成字符串属性值报错
  （`@name="hello"`），而不是静默不匹配。判断顺序是：
  **先看它是不是合法值列表；是就按值列表算，不是就按不支持的字符串报错。**
  所以 `@id="0-4 78"` 合法，`@name="hello"` 是语法错误。

### 3.6 `@prop`：超长选择

字符串 socket 装不下很长的选择时，节点会把完整内容存进**节点自己的 ID 属性**，
socket 里只留 `@prop`（或 `@prop:<名字>` 指定用哪个属性）。求值时把它替换回真正的字符串。
这一层对使用者是透明的。

## 4. 错误（Error）与警告（Warning）

**这条分界是规范的一部分。**

| 情况 | 反应 | 几何 | 选择 |
| --- | --- | --- | --- |
| **语法错误**（无法解析） | **Error** | 原样直通 | 全 false |
| **引用缺失**（组/属性不存在） | **Warning** | 正常 | 其余记号照常工作 |
| 组属性不是 BOOLEAN | **Warning** | 正常 | 该记号不匹配任何元素 |
| 索引超出范围 | 无 | 正常 | 该记号不匹配任何元素 |

语法错误包括：`5-2`、`0-3:0`、`1-`、`a-b`、`A.B`、`group:A`（`:` 不能出现在组名里）、
`arm[`（`[` 不配对）、`{0-3`（`{` 不配对）、`0-3 }`、`!`、`&`、`^`、`@`、`@position.y`
（缺比较运算符）、`@position.y>`（缺值）、`@position.q>0`（分量名非法）、
`@position.y>abc`（`>` 后面不是数）、`@position.y>0-4`（同上，`>` 不接值列表）、
`@name="hello"`（带引号且不是数值列表 → 不支持的字符串属性）、
`@position.y>"0-4"`（`>` 又不接值列表，所以引号里是字符串）。

## 5. 完整示例

设 `Domain = Point`，网格 12 个点，`group:A = {0,1,2}`，`group:B = {1,2,3}`，
组名还有 `arm`、`arm2`、`armX`、`leg`、`slim`。下表"选中"列是**规范答案**，
测试期望值由此推导（`test_selection_patterns.py` / `test_pdt_selection.py` 逐条断言）。

| 表达式 | 选中 | 说明 |
| --- | --- | --- |
| `*` | 全部 12 | |
| `0-3` | `{0,1,2,3}` | |
| `0-7:2` | `{0,2,4,6}` | 步长 |
| `0-1 4-5` | `{0,1,4,5}` | 并集 |
| `0-1,4-5` | `{0,1,4,5}` | 逗号等价 |
| `^0-3` | `{4…11}` | 全集起步 |
| `* ^3` | 除 3 以外 | |
| `A` | `{0,1,2}` | 组 |
| `A B` | `{0,1,2,3}` | |
| `A &B` | `{1,2}` | 交 |
| `A ^B` | `{0}` | 减 |
| `!A` | `{3…11}` | 空集起步，加补集 |
| `&A` | `{0,1,2}` | 全集起步，取交 |
| `A &B 0` | `{0,1,2}` | **左到右**：先 `A∩B`，再并 `0` |
| `0 &A &B` | `{}` | `{0} ∩ A ∩ B` = 空 |
| `A !B` | `{0,1,2,4…11}` | A ∪ ¬B |
| `A !B ^2` | 上一行去掉 2 | |
| `!A &B` | `{3}` | ¬A ∩ B |
| `{arm*}` | `arm∪arm2∪armX` | 子表达式 |
| `{arm* ^arm2}` | `(arm∪arm2∪armX) \ arm2` | 内部独立求值 |
| `{arm* &arm2}` | `arm2` | |
| `!{arm*}` | `arm*` 的补集 | |
| `{^0-3}` | `{4…11}` | 内部只有减号 → 内部从全集起步 |
| `?*` | 所有组的并集 | |
| `* ^?*` | 不属于任何组的元素 | |
| `@position.x>8` | x > 8 的点 | |
| `@ptnum>9` | 序号 > 9 的点 | |
| `@position.x&3` | `x & 3 != 0` 的点 | 按位与 |
| `@id="0-4 78"` | id ∈ {0..4, 78} | 值列表 |
| `0-1 @position.x>8` | 序号 0-1 加上 x>8 的点 | |
| `typo*` | `{}` + 一条警告 | 引用缺失不是错误 |
| `0-10 typo` | `{0…10}` + 一条警告 | 其余照常 |
| `5-2` | Error，几何直通、全 false | 语法错 |

## 6. 与 Houdini 的差异（有意）

| Houdini | 这里 | 原因 |
| --- | --- | --- |
| `@P`、`@x`、`@y`、`@z` | **不支持**，写 `@position.x` | Blender 的内置属性叫 `position`；不做别名以免"文档说能用其实不能" |
| `@name=字符串` | 语法错误 | Blender 的字符串属性不在常规 accessor 里，猜不如报错 |
| 组名前缀回退（`group_` 等） | 不支持 | 只认 `group:<名字>`，和 `Set/Store Named Attribute` 一致 |
| `group_` / `@group_` 拼法 | 不支持 | 同上 |
